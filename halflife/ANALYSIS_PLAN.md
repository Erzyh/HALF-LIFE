## 1. 결론 생존 판정 기준 (고정 대상)

재실행 결과와 원 논문 보고값의 비교는 3단 판정으로 한다.

- **생존**: 효과 방향 동일, 원 논문이 통계 검정을 보고한 경우 유의성 유지, 효과크기의 부호와 크기급(order of magnitude) 유지
- **부분 생존**: 방향은 동일하나 유의성 또는 크기급이 달라짐
- **사망**: 방향이 뒤집히거나 핵심 주장(예: "X를 못한다")이 성립하지 않음

절차: 판정자 3인(공저자)이 독립 코딩(자동 판정 스크립트 + 수기 확인) → 다수결, 3인 모두 다르면 "판정 불능"으로 별도 집계하고 본문 분석에서 제외 사유를 명시한다. 판정 시점에 어느 조건(생전/후속/오픈)의 결과인지 가려서(blind) 코딩한다.

## 2. 통계 계획

- **생존분석**: Kaplan-Meier(출판 연도 코호트별·도메인별), Cox 비례위험(공변량: 도메인, 의존 유형, 아티팩트 공개 수준, 스냅숏 표기 여부). 살아있는 모델 사용 논문은 우측 중도절단. 비례위험 가정은 Schoenfeld 잔차로 점검하고 위반 시 층화 Cox로 대체.
- **H2 검정**(주장 유형별 생존율 차이): 주장 단위 분석에 논문 단위 군집을 반영(클러스터 표준오차 또는 혼합효과 로지스틱). 목표 검정력 0.8, 두 비율 60% vs 40% 기준 그룹당 약 100 주장.
- **다중비교**: 사전 지정 가설(H1–H4)은 개별 보고, 탐색 분석은 Benjamini-Hochberg 보정 후 탐색적임을 명시.
- **민감도 분석**: ① Azure 등 대체 채널 잔존 시나리오(사망 판정 완화판) ② 별칭만 표기한 논문의 최선/최악 경계 ③ 프리프린트 포함/제외 ④ 도메인 불균형 가중.

## 3. 강건성 프로토콜

- 재실행은 시드 3회 × 프롬프트 패러프레이즈 2종. 판정은 중앙값 기준, 산포는 부록에 전량 보고.
- 온도 등 생성 파라미터는 원 논문 보고값을 따르고, 미보고 시 결정적 설정(temperature 0)과 그 사실을 기록.
- 프롬프트 민감도가 판정을 뒤집는 사례는 "민감(fragile)" 플래그로 별도 집계 — 은폐하지 않고 그 자체를 결과로 보고.

## 4. 자기 적용 — 이 연구 자신의 재현성 보증

우리가 제안하는 보존 프로토콜을 이 연구에 먼저 적용한다. 리뷰어 공격 지점을 선제 차단하는 목록:

| 조치 | 구현 |
|---|---|
| L1 영구 보존 | 전 API 호출의 요청·응답 전문 로그 아카이브(해시 포함) 공개 — 우리 결과는 모델이 죽어도 재검증 가능 |
| 스냅숏 고정 | 호출은 dated 스냅숏으로, 응답 헤더의 실제 서빙 버전을 로그에 병기 |
| 영구 재실행 축 | 오픈 가중치 모델 팔(Llama·Qwen, 버전·가중치 해시 고정)을 모든 비교에 포함 |
| 판정 기준 선고정 | 본 문서 동결 + 커밋 해시. 저장소 이력이 타임스탬프 증거 |
| 코딩 신뢰도 | 의존 분류 수기 검증 ≥500편, Krippendorff α와 짝별 κ 보고. 재실행 판정은 3인 코딩·다수결 |
| 검색 재현성 | 검색 문자열·일자·API 버전·제외 사유를 PRISMA형 흐름도로 보고, 센서스 데이터셋 DOI 기탁 |
| 수치 표기 규약 | 의존 분류 전 수치는 항상 "원시 상한"으로 라벨링 — 원시치와 확정치를 본문에서 혼용하지 않음 |
| 환경 고정 | requirements 버전 고정, 결정적 파이프라인, Code Ocean 캡슐(NMI 코드 리뷰 대응) |
| FP 투명성 | 전문 매칭 오염 사례(연도 불가능 매치, 메타데이터 병합 오류)를 은폐하지 않고 정제 단계와 함께 보고 |

## 5. 수기 검증 계획 (P1)

층화 표본 ≥500편(도메인 × 상태 × 연도), 코더 3~4인. 파일럿 30편은 전원 코딩, 본표본은 논문당 2인 순환 배정(3인 체제 각 333~334편, 4인 체제 각 250편), 불일치는 해당 논문을 보지 않은 코더가 결정. 코드북 사전 배포, 파일럿 α ≥ 0.7 미달 시 코드북 수정 후 재코딩(수정 이력 보존). 보고 지표: Krippendorff α(명목), 짝별 Cohen κ, 층별 정밀도·재현율.
