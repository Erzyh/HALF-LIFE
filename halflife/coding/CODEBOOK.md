# HALF-LIFE 의존 분류 코드북 v1.3

2026-09-05 초판, 2026-09-18 v1.1(파일럿 불일치 반영), 같은 날 v1.2(공저자 회의 결정: 역할 코드를 3+1개 한글 코드로 통합, Q4 삭제, 실행 모델 칸 추가), 2026-09-27 v1.3(파일럿 v1.2 검토 반영: Q1은 상용 모델의 경로만, Q2 병합 규칙, 참고문헌 URL은 인용·언급, 판단불가 처리, 실행 모델 칸의 순서). 개정 내용은 맨 아래 "개정 이력"에 남긴다.

## 0. 이 작업이 무엇인가

센서스는 27,044편의 논문에서 특정 모델 ID 문자열(예: gpt-4-0613, gemini-1.5-pro)이 본문에 나오는 논문을 모았다. 이 55개 ID는 이미 단종됐거나 단종일이 공지된 모델이라서, 논문이 그 모델에 기댔다면 "출판 뒤 몇 달 만에 모델이 사라졌는가"를 잴 수 있다. 문제는 문자열이 나온다고 그 논문의 결과가 그 모델에 의존하는 것은 아니라는 점이다. 관련연구에서 언급만 했을 수도 있고, 참고문헌 제목에만 있을 수도 있다.

그래서 표본 500편을 사람이 읽고 "이 ID를 실제로 실행했는가"를 판정하고, 그 비율로 센서스를 보정한다. 파일럿 30편은 그 전에 네 사람이 같은 논문을 코딩해 규칙이 같은 답을 내는지(일치도) 확인하는 단계다. 논문에 들어가는 숫자는 500편에서 나오고, 파일럿은 그 숫자를 믿을 수 있게 만드는 절차다.

재현이나 실행은 없다. 논문을 열어 읽고, 워크북의 노란 칸에 답을 고르는 일이다. 편당 2~4분을 목표로 한다.

## 1. 원칙

- 코더는 서로 상의하지 않고 독립적으로 코딩한다. 파일럿 30편을 끝내고 결과를 회신한 뒤에 불일치를 함께 본다.
- 코더는 4인이다. 파일럿 30편은 전원이 같은 논문을 보고, 본표본 500편은 논문마다 2인이 보도록 순환 배정한다(각 250편). 두 사람의 코드가 다르면 그 논문을 보지 않은 코더가 최종 코드를 정한다.
- 판단 근거는 논문 자체다. 워크북에 미리 뽑아둔 "근거 문장"은 찾는 수고를 덜기 위한 것이고, 확신이 서지 않으면 DOI 또는 OA 링크로 논문을 열어 Ctrl+F로 ID를 검색한다.
- 저자에게 문의하지 않는다. 논문과 논문이 가리키는 공개 저장소만 본다.
- 한 편에 10분을 넘기면 멈추고, 현재 판단을 적은 뒤 확신도를 "낮음"으로 표시하고 메모에 이유를 쓴다.
- 코드를 바꾸고 싶은 규칙이 있으면 메모에 적어 둔다.
- 파일럿을 다시 코딩할 때는 이전 답을 보지 않고 새 파일에 처음부터 적는다.

## 2. 단위

한 행이 논문 한 편이다. 각 행에는 센서스가 매칭한 모델 ID가 1~6개 미리 적혀 있다(ID1~ID6). ID마다 "역할" 코드를 하나씩 고른다. 그다음 "실행한 모델(전체)" 칸과 논문 단위 항목(Q1~Q3, Q5, Q6)을 채운다.

## 3. ID별 역할 코드

먼저 논문에서 그 ID(또는 그 ID를 포함하는 더 긴 ID, 그리고 그 별칭)가 나오는 모든 자리를 찾는다. 그 뒤 아래 순서로 판단한다.

| 코드 | 뜻 | 기준 |
|---|---|---|
| 실행 | 저자가 직접 실행 | 저자가 이 모델을 직접 호출해 결과를 얻었다. 평가 대상, 비교 베이스라인, 제안 방법의 백본, 미세조정, 심사자·라벨러·데이터 생성 같은 보조 도구, 사람에게 준 개입 모두 포함한다. 실행 결과가 표·본문·부록에 있거나 실행했다는 서술이 있어야 한다. |
| 인용·언급 | 실행하지 않음 | 관련연구·서론·논의의 언급, 참고문헌 제목, 다른 논문에서 가져온 수치를 넣은 비교표, 향후 연구 언급, 예시로 든 이름, 논문 작성 보조(문장 다듬기)에 썼다는 고지. |
| 못찾음 | 문자열이 없음 | 본문·부록·표·각주·참고문헌 어디에도 그 ID(별칭 포함)가 없다. 검색 오탐이다. 참고문헌의 제목·URL·모델 카드 링크에만 있어도 '인용·언급'이지 '못찾음'이 아니다(v1.3). |
| 판단불가 | 열 수 없음 | 전문을 열 수 없거나, 언어를 읽을 수 없거나, PDF가 깨졌다. 초록만으로 역할을 추정하지 않는다. 메모에 출처(예: ACM DL, IOS Press)와 시도한 경로를 적는다. 병합에서는 전문을 연 코더의 코드가 우선한다(v1.3). |

판단 순서:

1. ID가 나오는 자리를 모두 찾는다. PDF를 열어 Ctrl+F로 ID와 별칭(예: gpt-4-turbo, GPT-4 Turbo)을 찾는다.
2. 모든 등장 위치가 참고문헌 목록 안(제목·URL·모델 카드 링크 포함)이거나 관련연구·서론의 언급뿐이면 '인용·언급'.
3. 저자가 실행했으면 '실행'. 주 대상이든 베이스라인이든 심사자든 구분하지 않는다. 역할이 특이하면(예: 심사자로만 사용) 메모에 적는다.
4. 어디에도 없으면 '못찾음', 열 수 없으면 '판단불가'.

자주 나오는 경우:

- 본문은 "GPT-4 Turbo"라고만 쓰고 표나 부록에 gpt-4-1106-preview가 있다: 표의 ID가 매칭 ID이면 '실행'으로 코딩한다. 버전 표기 수준은 Q2에서 따로 묻는다.
- 매칭 ID가 더 긴 ID의 일부로만 나온다(예: 매칭 ID는 gpt-4-turbo인데 본문에는 gpt-4-turbo-2024-04-09만 있다): 긴 ID의 역할대로 코딩하고, "실행한 모델" 칸에 실제 문자열을 적는다.
- Azure OpenAI, Amazon Bedrock, Vertex AI, OpenRouter 등을 통해 같은 모델을 썼다: 그 모델을 쓴 것으로 본다. 경로는 Q1에 적는다.
- ChatGPT 웹 화면에서 실험했다: '실행'으로 코딩하고 Q1을 "웹UI"로 한다.
- 서베이·리뷰 논문이 모델을 설명만 한다: '인용·언급'. 실험을 돌렸으면 '실행'.
- "GPT-4(gpt-4-0613)와 GPT-3.5를 비교했다"에서 GPT-3.5는 버전이 없다: 버전 없는 이름은 매칭 대상이 아니므로 역할 코드를 붙이지 않는다. 다만 "실행한 모델" 칸에는 적는다.
- 논문이 실제로 쓴 모델이 시트의 ID 목록에 없다(예: gpt-4o-mini-2024-07-18, gpt-4.1, Claude 3.5 Sonnet): 그 모델은 "실행한 모델" 칸에 적고, 시트에 있는 매칭 ID는 그 ID의 실제 역할대로 코딩한다(목록 외 모델이 주 대상이고 매칭 ID는 언급만이면 '인용·언급').

## 4. 실행한 모델(전체)

저자가 직접 실행한 모델 전체를 논문에 적힌 가장 구체적인 표기 그대로, 쉼표로 구분해 한 줄에 적는다(줄바꿈 금지). 주 모델(논문의 질문이 그 모델의 성능·행동이거나 제안 방법의 백본인 모델)을 반드시 맨 앞에 둔다. 주 모델이 무엇인지 갈리면 메모에 적는다. 날짜 스냅숏을 찾았으면 그 문자열 그대로 적는다. Q2의 근거가 된다(v1.3). 상용이든 오픈 가중치든 모두 적는다. 언급만 된 모델은 적지 않는다. 실행이 없으면 비운다.

예: `gpt-4o-mini-2024-07-18, claude-3-5-sonnet, Llama-3.1-70B-Instruct`

이 칸은 세 가지에 쓴다. Q2의 기준 모델이 되고, 센서스 목록 밖 모델이 주 모델인 논문의 비율을 주고, 다음 단계에서 살아 있는 모델까지 넣은 센서스의 어휘가 된다.

## 5. 논문 단위 항목

Q1 접근 경로. 매칭된 상용 모델을 실험에서 어떻게 호출했는가. 하나만 고른다. (v1.3) 오픈 가중치 모델을 함께 로컬에서 돌렸더라도 상용 모델의 경로만 답한다. 파일럿에서 '불명'과 '혼합'이 가장 많이 갈렸다.

| 값 | 뜻 |
|---|---|
| API | 프로그램으로 호출(OpenAI·Anthropic·Google API, SDK, 배치 API). "API"라는 말이 없어도 SDK, 호출 코드, temperature 같은 호출 파라미터가 적혀 있으면 API |
| 웹UI | ChatGPT·Gemini·Claude 채팅 화면에서 직접 입력 |
| 혼합 | 같은 상용 모델을 두 경로로 불렀다(예: 1차 실험은 ChatGPT 웹 화면, 2차는 API). 상용 모델은 API로, 오픈 모델은 로컬로 돌린 경우는 '혼합'이 아니라 'API'다 |
| 클라우드배포 | Azure OpenAI, Bedrock, Vertex AI 같은 클라우드 배포 |
| 서드파티 | OpenRouter, Together 등 중개 서비스 |
| 로컬 | 매칭된 모델의 가중치를 내려받아 직접 실행. 매칭 ID는 상용 API 모델이라 드물다 |
| 해당없음 | 실행한 모델이 없음(역할이 인용·언급이나 못찾음뿐) |
| 불명 | 실행은 했는데 경로 단서가 전혀 없음. temperature·top_p·max_tokens 같은 호출 파라미터, SDK, 호출 코드, 코드 저장소가 있으면 '불명'이 아니라 'API' |

Q2 버전 표기 수준. "실행한 모델" 목록의 첫 모델(주 모델)을 어떻게 표기했는가.

| 값 | 예 |
|---|---|
| 날짜 스냅숏 | gpt-4-0613, gpt-4o-2024-05-13, claude-3-opus-20240229, o1-2024-12-17, text-davinci-003 |
| 별칭·계열명 | gpt-4-turbo, gpt-4o, gpt-4, gpt-3.5-turbo, claude-3-5-sonnet, gemini-1.5-pro, o1-preview, o3-mini |
| 제품명 | ChatGPT, GPT-4, Gemini, Claude, Copilot |
| 해당없음 | 실행이 없음 |

논문 어디든(본문, 표, 각주, 부록, 보충자료, 저장소 README나 설정 파일 포함) 날짜 스냅숏이 하나라도 있으면 '날짜 스냅숏'. 본문에 별칭만 있으면 '별칭·계열명'. 찾는 순서는 표와 부록의 모델 설정 절, 각주, 저장소 README다. "모델ID참조" 시트에 매칭 대상 ID 55개가 어느 유형인지 적혀 있다. (v1.3) 병합 규칙: 코더 한 명이라도 날짜 스냅숏을 찾아 실행 모델 칸에 그 문자열을 적었으면 그 논문의 Q2는 '날짜 스냅숏'이다. 찾은 것은 증거이고 못 찾은 것은 증거가 아니다. 그러므로 찾았을 때는 문자열을 반드시 적는다.

Q3 실행 시점. 모델을 언제 호출했는지 적혀 있는가. 연월 / 연도만 / 없음 / 해당없음(실행 없음). "accessed March 2024", "실험은 2024년 5월에 수행" 같은 문장이면 연월. 논문 투고일이나 학회 일자는 해당하지 않는다.

Q5 열람. 전문 / 초록만 / 불가. 전문을 열었으면 "전문".

Q6 확신도. 높음 / 낮음. 낮음이면 메모에 이유.

메모. 자유 기술. 판단이 어려웠던 이유, 코드북에 없는 상황, 특이한 역할(심사자로만 사용 등).

소요(분). 선택 사항. 한 편에 걸린 대략의 시간.

(v1.1까지 있던 Q4 공개 아티팩트 항목은 삭제했다. 코드 링크는 자동 스캔이 있고, 데이터·출력 공개 여부는 Tier B 트리아지가 확인한다.)

## 6. 절차

1. 파일럿 30편을 각자 코딩해서 파일을 회신한다(전원 같은 30편). 파일명은 바꾸지 않는다.
2. 파일을 합쳐 일치도(Krippendorff α, 짝별 κ)를 계산하고, 불일치 목록을 놓고 이야기한다. 규칙이 바뀌면 이 문서에 개정 이력을 남긴다.
3. 파일럿의 역할 코드 α가 0.7에 못 미치면 개정된 코드북으로 파일럿 30편을 전원이 다시 코딩하고 α를 다시 계산한다. 회의에서는 개별 논문의 정답을 정하지 않고 규칙 문장만 정한다. 재코딩은 다시 독립적으로 한다. (v1.2 파일럿 결과, 2026-09-27: 역할 α 0.78, 의존/비의존 α 0.94로 통과. 재코딩 없이 본표본으로 간다. 근거는 `coding/PILOT_REVIEW_v12.md`.)
4. 본표본은 배정된 논문(4인 체제 250편)을 각자 코딩한다. 하루 20편이면 2주 안팎이다. 중간에 파일을 보내도 된다.
5. 본표본이 끝나면 불일치 목록을 만든다. 각 불일치는 그 논문을 보지 않은 코더가 두 코드 중 하나를 고르거나 새 코드를 정하고(`disagreements_main.csv`의 tie_breaker 열), 그 결정을 기록한다. 교신저자는 조정에 참여하지 않는다. 두 코더가 모두 '판단불가'이면 제3코더가 원문 확보를 다시 시도하고, 그래도 없으면 그 논문은 제외하고 그 비율을 보고한다(v1.3).

## 7. 결과가 어디에 쓰이는가

- ID별 역할 코드는 "의존"(실행)과 "비의존"(인용·언급, 못찾음)으로 묶어 센서스를 보정한다. 층별(모델 상태 × 분야) 비율과 코더 간 Krippendorff α, 짝별 κ를 보고한다. 이것이 이 코딩의 핵심 산출물이다.
- Q2는 버전 표기율(가설 H3). Q1은 웹UI 실험 비율(스냅숏이 아예 없는 층). Q3은 별칭 규칙(출판일로 스냅숏을 추정)의 검증.
- "실행한 모델(전체)"은 목록 외 모델 비율과 어휘 확장의 재료.
- Q6 확신도는 코더 성향이 강해(파일럿에서 α < 0) 통계에 쓰지 않는다. 메모의 이유만 읽는다(v1.3).
